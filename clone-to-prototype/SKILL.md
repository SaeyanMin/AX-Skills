# clone-to-prototype

## 개요

로컬에 클론된 프론트엔드 레포의 **현행 화면 코드를 읽어서**, 외부 의존성이 전혀 없는 정적 3파일(`index.html` / `style.css` / `index.js`) 프로토로 포팅한다. 단순 임시 확인부터 **버전 관리되는 화면설계 산출물**까지 스코프를 골라 진행한다. 로컬 서버 없이 `open index.html`로 브라우저에서 바로 확인한다.

**대전제**: 참고할 프론트엔드(및 필요시 백엔드) 레포지토리가 **이미 로컬에 클론되어 있다**. 라이브 앱을 실행(`npm run dev` 등)하지 않는다. 디자인·구조·라벨·분기·스타일은 전부 클론된 레포의 소스코드(컴포넌트·CSS·i18n 문구)를 읽어서 재현한다.

## 시작 절차 (코드 읽기 전 반드시 수행)

`AskUserQuestion`으로 아래를 확정한 **뒤에야** 코드를 읽고 포팅을 시작한다.

```
0) 커버 범위(스코프)는 어디까지인가?
     T1 프로토만       → 3파일을 지정 폴더에 생성 + open. 임시 확인용. 버저닝·템플릿 없음.
     T2 버저닝 저장    → 3파일을 prototypes/{화면키}/v{N}/ 에 저장 + meta.json. 이전 버전 보존.
     T3 화면설계 세트  → T2 + specs/{화면키}/v{N}/spec.md. 스펙↔프로토를 화면키·버전으로 짝.
1) 대상 프론트엔드 레포가 로컬에 클론돼 있는가?
     └ 안 돼 있으면 → 클론부터 하도록 안내하고 여기서 중단. (앱을 실행하지 않는다)
2) 어떤 레포지토리(로컬 경로)를 참고하는가?
     └ 필요하면 관련 백엔드 레포 경로도 함께 확인 (분기·상태·라벨의 근거)
3) 어떤 화면/컴포넌트를 프로토로 만드는가?
     └ 화면 이름·라우트·컴포넌트 파일을 특정. 애매하면 후보를 나열해 고르게 한다.
4) 산출물을 어디에 두는가? (출력 경로)
     └ 참고 레포를 오염시키지 않도록, 매번 사용자에게 물어 지정된 폴더에 생성한다.
     └ T2/T3면 그 위치의 자체 규약을 먼저 감지한다 (아래 "자체 규약 우선").
```

이 항목들이 확정되기 전에는 코드를 읽지 않는다.

## 자체 규약 우선 (T2/T3)

출력 위치(또는 그 상위)에 프로젝트 **자체 규약**이 있으면 스킬 내장 기본값보다 **그것을 우선 적용**한다. 감지 대상:

- `README.md` / `_templates/` / `CLAUDE.md` 등 폴더 구조·버저닝·네이밍·커밋 규약 문서
- 이미 존재하는 `specs/` · `prototypes/` 구조와 기존 `화면키`·`v{N}` 패턴
- 기존 `meta.json` / `spec.md` 스키마

감지되면 그 폴더구조·버저닝·화면키 네이밍·템플릿·커밋(브랜치/싱크) 규약을 그대로 따른다. 없을 때만 아래 범용 기본값과 `templates/`의 파일을 사용한다.

## 범용 폴더 스키마 & 버저닝 (자체 규약 없을 때 기본값)

```
{out}/
├── specs/{화면키}/v{N}/{spec.md, meta.json}
└── prototypes/{화면키}/v{N}/{index.html, style.css, index.js}
```

- 채널이 여럿이면 상위에 채널 폴더(`com/`, `adm/` 등)를 두고 그 아래 `specs`/`prototypes`.
- **화면키**: 도메인 접두어로 충돌 방지 (`member-register`, `order-list`…). **그룹핑은 폴더가 아니라 `meta.json`의 `groupName`.**
- **버전**: 최초 `v1/`, 변경 시 **새 버전 폴더(`v2/`) 추가하고 이전 버전 보존**. `meta.json`의 `prototype.latest` 갱신.
- 템플릿: `templates/spec.template.md`, `templates/meta.template.json`, 출력 루트 규약 문서는 `templates/README.template.md`. 플레이스홀더(`{...}`)를 채워서 생성한다.

## 원칙: 실제 렌더 결과의 복제 (예측 금지)

프로토는 대상 화면 컴포넌트의 **실제 렌더 출력을 그대로 옮긴 것**이다. 화면을 새로 설계하는 게 아니다.

1. 컴포넌트의 `render`를 끝까지 읽는다 — 조건부 분기(삼항·early return·`enabled` 플래그·`?? []`·`map`)와 위임하는 하위 컴포넌트까지. 상태·문구·구조는 전부 이 분기에서 나온다.
2. **나온 것만 그린다.** 코드가 그리지 않는 상태/문구/요소는 만들지 않는다(없는 안내문·기본 노출·가짜 버튼 금지). 초기/로딩/빈/에러는 코드에 그 분기가 **있을 때만** 존재한다 — 따로 "상상"하지 않는다.
3. 근거를 못 대는 요소는 넣지 않는다 → 비우거나 "확인 필요"로 남기거나 사용자에게 묻는다.
4. 문구는 코드의 실제 i18n·문자열만. 주석·동작 설명·추측을 UI 카피로 바꾸지 않는다.

## 실행 절차 (소스 → 3파일)

라이브 화면을 보는 게 아니라 **소스를 근거로 재현**한다. 아래는 전부 "실제 값 그대로" — 눈대중·근사치·창작 금지.

**1) 구조·클래스·라벨**
- 대상 컴포넌트를 읽어 DOM 계층·순서·시맨틱과 **실제 클래스명·라벨(i18n)** 을 그대로 옮긴다. 자기 클래스명을 지어내지 않는다.
- ★ 벤더/유틸 CSS는 **정확한 셀렉터 구조에서만** 먹는다. 래퍼 클래스가 틀리면(예: `.nav` vs `.navbar-nav`) 스타일이 안 붙어 기본색이 새어나온다. "색/폰트가 다르다"의 대부분이 이 래퍼/계층 불일치 → 해당 CSS 셀렉터를 grep해 요구 구조에 DOM을 맞춘다.
- 앱 셸(좌측 네비/상단 헤더)도 실제 레이아웃·네비 컴포넌트에서 읽어 그대로. 실제 없는 요소(브레드크럼 등) 지어내기 금지.

**2) 스타일 (CSS를 손으로 짜지 않기)**
- 실제 사용 스타일을 그대로 가져온다. 우선순위 ① 빌드/컴파일된 스타일시트(`public/**/*.css`, `dist/`, `build/`, 테마 `*.min.css`) ② 없으면 소스(SCSS/LESS/CSS) 컴파일·원문.
- 그 CSS를 **셸로 이어붙여** `style.css`로 인라인한다(모델이 본문을 붙여넣지 말 것 — 토큰 낭비·누락). 예: `cat theme.min.css user.min.css > style.css`. 외부 URL 참조(`@import`·`url(http…)` 웹폰트)만 제거 → 시스템 폰트 폴백. 색·간격·폰트 값을 임의로 정하지 않는다.

**3) 자산**
- 로고·아이콘 등은 레포의 실제 파일을 **data URI로 인라인**(텍스트 대체 금지). 예: `base64 -i logo.png` → CSS `background`/`img src`. 외부 URL 금지.

**4) 분기·상태·동작**
- 조건부 렌더(로딩/에러/빈/권한/토글)와 인터랙션(검색·필터·정렬·탭·조건부 표시)을 **소스 분기대로** `index.js`의 순수 DOM 조작으로 재현한다. 데이터가 필요하면 백엔드 응답 형태를 참고해 **정적 목데이터**로 인라인. 클릭 무반응 가짜 버튼 금지. 정적 3파일 규칙상 금지 API(`window.open`·`location`·`alert` 등)는 인페이지 동작으로 대체. (T3면 각 상태를 `spec.md` 케이스표에 ID로 적재해 프로토와 매칭)

**5) 검증 (필수 — 눈으로 안 보고 완료 선언 금지)**
- 헤드리스로 스크린샷을 떠 실제와 대조: `"$CHROME" --headless=new --screenshot=shot.png --window-size=1440,1000 "file://<절대경로>/index.html"`
- 어긋나면 CSS를 손대기 전에 그 요소의 실제 컴포넌트/CSS 셀렉터를 다시 읽어 원인(대개 래퍼 클래스·마크업 계층)을 잡는다. 맞을 때까지 반복.

핵심 한 줄: 디자인·구조·라벨·자산·동작 전부 클론 레포에서 읽은 실제 값. 안 맞으면 CSS를 손대지 말고 "실제가 요구하는 DOM 구조"에 맞춘다.

## 정적 3파일 규칙 (반드시 준수 — 모든 티어 공통)

**금지**

| 항목 | 이유 |
|------|------|
| 외부 CDN/폰트/CSS/JS/이미지 URL | 자체완결 위반. 전부 인라인/CSS로 그린다 |
| 프레임워크·라이브러리 (React/Vue/jQuery 등) | Vanilla JS만 사용 |
| ES module (`type="module"`, `import`/`export`) | classic script만 사용 |
| `localStorage` / `sessionStorage` | 스토리지 접근 금지 |
| `alert` / `confirm` / `prompt` | 네이티브 다이얼로그 금지 |
| `window.open` / `location` 이동 | 페이지 이탈 금지 |
| `eval` | 금지 |
| `document.body`에 직접 append | 금지 |

**필수**

- `index.js`는 `DOMContentLoaded`로 감싸지 말고 **IIFE**로 즉시 실행: `(function(){ ... })();`
- DOM은 `#app` 등 **컨테이너 요소에 append** (body 직접 조작 금지)
- 주요 블록에 **안정적인 `id`** + **시맨틱 태그**(`<header>`/`<nav>`/`<main>`/`<section>`/`<button>` 등) 사용
- `index.html`이 `style.css`와 `index.js`를 로컬 상대경로로 참조

## 산출물 & 확인

| 티어 | 생성물 |
|------|--------|
| T1 | `index.html` / `style.css` / `index.js` (지정 폴더) |
| T2 | 위 3파일을 `prototypes/{화면키}/v{N}/`에 + `specs/{화면키}/v{N}/meta.json` (+출력 루트에 규약 README 없으면 생성) |
| T3 | T2 + `specs/{화면키}/v{N}/spec.md` (케이스표 포함) |

1. 3파일 각각을 **코드블록으로 출력**한다.
2. 동시에 지정된 경로에 **실제 파일로 생성**한다 (T2/T3면 스키마 폴더 + 템플릿 채운 산출물 포함).
3. 로컬 HTTP 서버를 띄우지 않는다. `open <경로>/index.html`로 브라우저에서 바로 연다.

## 흔한 실수

- 라이브 앱을 실행해 화면을 보려 함 → 금지. 소스만 읽는다.
- 문구/색을 눈대중으로 추정 → i18n·CSS 소스에서 실제 값을 가져온다.
- 편의상 CDN(폰트·아이콘·CSS 프레임워크) 링크 → 자체완결 위반. 인라인한다.
- `DOMContentLoaded` 래핑 → IIFE 즉시 실행으로 바꾼다.
- 참고 레포 폴더 안에 프로토를 생성해 레포를 오염 → 출력 경로를 별도로 지정받는다.
- T2/T3에서 자체 규약을 무시하고 범용 기본값을 덮어씀 → 먼저 감지해 있으면 그걸 따른다.
- 기존 버전을 덮어씀 → 변경은 새 `v{N}` 추가, 이전 버전 보존.
- 비밀정보(토큰·사내 URL·비공개 경로·사내 코드베이스명)를 산출물에 포함 → 절대 금지.
